## Context

打包版本目前通过 `可执行文件目录/data` 解析数据库、日志、设置、备份和更新目录。该行为在安装位置稳定时可用，但 Inno Setup 会按 AppId 记忆安装位置；发布冒烟使用正式 AppId 后，开始菜单被改到临时目录，应用随即在临时目录创建空数据库。用户的原数据库完整存在，却因路径静默切换而表现为数据丢失。

当前已有 `BARBYBAR_DATA_DIR` 覆盖、SQLite 一致性备份和恢复校验能力。修复必须兼容源码运行、显式覆盖和既有相邻数据目录，且不能在启动过程中复制大型数据库或覆盖冲突数据。

## Goals / Non-Goals

**Goals:**

- 让打包应用的数据选择不再随安装目录或快捷方式变化。
- 对现有相邻数据库执行零复制接管，并在稳定的用户级定位文件中记录选择。
- 在创建新数据库前识别旧数据；遇到多个含用户数据的候选时阻止静默选择。
- 让设置页和日志能够解释“当前用的是哪个目录、为什么”。
- 隔离安装器冒烟测试与正式 AppId、快捷方式及卸载记录。

**Non-Goals:**

- 本补丁不修改 SQLite 业务表结构。
- 本补丁不在启动时自动复制大型数据库到新目录。
- 本补丁不删除临时空库、旧安装目录数据库或用户手工指定目录。
- 本补丁不提供任意目录之间的完整数据合并功能。

## Decisions

1. **使用稳定定位文件，而不是继续依赖可执行文件路径。** 打包版本在 `%LOCALAPPDATA%/BarByBar/data-location.json` 保存绝对数据根目录；默认新数据目录为 `%LOCALAPPDATA%/BarByBar/data`。定位文件位于安装目录之外，因此升级、重装和安装路径变化不会改变选择。相比立即搬迁数据库，零复制绑定没有长时间启动阻塞，也保留原文件位置。

2. **保持明确的解析优先级。** `BARBYBAR_DATA_DIR` 始终最高；其次是有效定位文件；再次是旧数据库发现；最后才创建稳定默认目录。源码开发模式继续默认使用项目 `data`，避免改变测试和开发工作流。

3. **仅自动接管唯一的有效候选。** 打包模式发现当前可执行文件相邻目录和历史默认安装目录中的数据库时，使用只读轻量检查确认 SQLite 头、关键表和是否包含用户数据。只有一个含用户数据的有效候选时才写入定位文件并接管；多个含用户数据的候选会抛出可诊断冲突，应用在创建 Repository 前显示路径并停止，避免选择错误数据。

4. **原子写入定位文件。** 定位文件先写临时文件、刷新磁盘后通过 `os.replace` 发布；无效、相对、不可解析的定位文件不会触发数据库创建，并提供明确错误。

5. **解析只发生一次并携带来源信息。** 路径模块返回包含根目录和来源的解析结果，供日志和设置页展示；同一进程缓存该结果，保证数据库、日志、设置和备份始终落在同一根目录。

6. **安装冒烟使用独立 AppId。** Inno 脚本允许构建时传入 `MyAppId`，发布脚本额外构建测试安装器或以测试 AppId 编译后再进行临时安装；正式产物仍使用稳定生产 AppId。冒烟前后验证正式快捷方式目标和卸载记录未变化。

## Risks / Trade-offs

- [定位文件指向已移动或不可访问目录] → 启动前报错并显示定位文件和目标路径，不创建替代空库；用户可通过显式覆盖恢复。
- [多个历史数据库都包含数据] → 不按文件大小或时间猜测，阻止启动并列出候选，避免误选。
- [定位文件泄露本地路径] → 文件仅保存在当前用户 LocalAppData，不包含业务数据或凭据。
- [旧数据库仍位于安装目录] → v0.6.1 先以零复制方式稳定绑定；后续版本可提供用户主动、安全备份式迁移到标准目录。
- [安装测试仍污染用户状态] → 测试 AppId、测试程序组和临时安装目录三重隔离，并增加脚本级回归检查。

## Migration Plan

1. 用户升级到 v0.6.1 后，显式环境覆盖继续原样生效。
2. 无覆盖且无定位文件时，程序在创建数据库前扫描兼容候选。
3. 唯一有效旧数据库被零复制绑定，并原子保存定位文件；原数据库路径和内容不变。
4. 没有旧数据的全新安装使用稳定默认目录。
5. 多个有效数据库时停止自动启动并显示冲突路径；任一数据库都不修改。
6. 回滚到 v0.6.0 时原数据库仍保留在原位置；可通过 `BARBYBAR_DATA_DIR` 继续访问。
