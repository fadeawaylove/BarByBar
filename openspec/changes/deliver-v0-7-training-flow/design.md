## Context

当前 `MainWindow.create_session_for_dataset()` 使用固定的 `min(50, len(bars)-1)` 起点，`Repository.create_session()` 立即创建 `active` 案例；用户没有机会在开始前定义训练目的或确认起点。`ReviewEngine.complete()` 也只切换状态并保存，未平仓处理、结束摘要和完成后的导航均没有独立流程。案例模型目前只有 `active/completed` 状态、通用 notes/tags 和交易统计，无法表达“已准备但尚未开始”或保存训练简报。

v0.7 跨越模型、数据库、仓储、数据集入口、案例库、主工作台和完成界面。实现必须保持本地优先、兼容已有数据库与案例、避免在准备阶段泄露随机起点后的未来行情，并继续沿用 v0.6 的保存失败恢复和发布质量门槛。

## Goals / Non-Goals

**Goals:**

- 建立准备、开始、恢复、完成和总结的显式生命周期。
- 让起点选择、训练目标和本次规则成为可验证、可持久化的案例上下文。
- 为手动完成提供安全的未平仓处理和事实型摘要。
- 让案例库能够清楚区分未开始、训练中和已完成案例。
- 为旧数据库提供自动、可回退的增量迁移，不改变历史交易语义。

**Non-Goals:**

- 不实现纪律评分、逐笔结构化评价、策略模板评分或跨案例洞察；这些属于 v0.8/v0.9。
- 不改变撮合、订单触发、持仓、盈亏和现有逐根回退语义。
- 不引入账号、云同步、联网行情或多人协作。
- 不在本变更中重复极端绘图性能架构任务。

## Decisions

### 1. 使用 `prepared → active → completed` 的显式状态机

在现有 `SessionStatus` 中增加 `PREPARED`。准备确认后先事务性创建 prepared 案例；只有用户点击“开始训练”后才转为 active。已 active 的旧案例按原样恢复，completed 案例保持只读完成语义。

选择显式状态而不是从“是否发生过动作”推断阶段，因为打开案例、修改备注或保存界面设置都不等于训练已经开始；显式状态也让案例库和恢复流程可测试。状态转换集中在领域/仓储边界并拒绝 completed 回到 active 的隐式转换。

### 2. 使用结构化训练简报，而不是复用通用 notes/tags

为案例增加训练目标、规则列表、起点策略、完成反思、下次关注点和完成时间等向后兼容字段。规则以版本化 JSON 数组持久化，读取时规范化为空列表并容忍未知未来字段；用户自由备注继续保留原用途。

选择独立字段是为了避免目标、规则和复盘笔记互相覆盖，并为 v0.8 的结构化评价保留迁移空间。v0.7 不保存纪律分数或“是否遵守”复选结果。

### 3. 起点解析采用纯配置与事务创建两阶段

准备界面先读取数据集元数据和可用索引边界，生成 `SessionPreparation` 配置；仓储在确认时再次校验并一次性解析最终起点、插入案例。支持明确起点和随机起点，默认保证足够的历史观察 K 线，并预留至少一根可推进 K 线。

随机模式在点击开始前只显示候选范围和数量，不显示解析后的时间戳、价格或未来区间。随机选择逻辑提取为可注入随机源的纯函数，便于边界与可重复测试。创建失败不得留下半成品案例。

### 4. 准备和完成使用短流程对话框，工作台只保留安静上下文

准备流程采用分组对话框呈现数据、起点、目标、规则和最终确认；不把大量低频字段塞进主工作台。训练中在案例头部或侧栏提供可折叠的目标/规则摘要和阶段徽标，图表与高频操作保持主导。

完成流程使用专用对话框显示目标、规则、事实统计和自由文本反思。若仍有持仓，用户必须选择“按当前 K 线平仓并完成”或“返回训练”；系统不允许悄悄丢弃持仓。完成后可进入交易复盘或返回案例库。

### 5. 完成摘要只使用可复算事实，主观评分延后

摘要包含训练区间、推进 K 线数、交易数、胜负、净盈亏、最大回撤、持仓时长等现有数据可稳定计算的事实，以及用户填写的完成反思和下次关注点。摘要视图模型独立于数据库列名，重新打开 completed 案例时从持久化会话和交易记录复算。

选择事实摘要可立即闭合流程，又不会提前固化 v0.8 尚未设计好的纪律模型。

### 6. 采用增量、幂等 SQLite 迁移

迁移只新增带默认值的列和必要索引，不重写动作或交易表。迁移前继续使用 v0.6 的数据库安全备份能力；迁移函数可重复执行，并通过旧版本数据库夹具验证。读取旧行时所有新字段均有明确默认值。

## Risks / Trade-offs

- [训练准备字段过多导致流程变重] → 首版只要求数据、起点和目标，规则允许为空；提供清晰默认值与单页分组，不引入策略模板编辑器。
- [随机起点泄露未来信息] → 解析前只展示候选范围统计；随机结果在开始时才揭示当前上下文；自动化测试禁止准备摘要出现未来 OHLC 或结束时间。
- [新增状态破坏旧案例恢复] → 旧 `active/completed` 值保持不变，新列均有默认值，迁移夹具覆盖加载、保存和继续训练。
- [手动平仓改变用户原本想保留的持仓] → 完成按钮必须显式确认，默认操作是返回训练，不提供无提示自动平仓。
- [完成摘要与后续结构化复盘重复] → v0.7 仅保存自由文本和事实数据，不创建评分字段；v0.8 在稳定生命周期之上扩展。
- [对话框与案例库改动扩大 UI 回归面] → 延续关键状态截图、窄屏、键盘焦点、保存失败和打包字体检查。

## Migration Plan

1. 为新模型和迁移增加旧数据库夹具测试，确认升级前自动备份路径可用。
2. 增加新列、状态解析和仓储 API，旧创建 API 保留兼容包装直到调用点迁移完毕。
3. 接入准备流程，再迁移案例库与工作台的阶段展示。
4. 接入完成确认和摘要，最后移除固定第 51 根起点的直接创建路径。
5. 完成全量、视觉、迁移和安装包验证后发布 v0.7.0。

回退代码版本时保留新增列；旧版本会忽略新列，但不得打开 `prepared` 案例进行训练。若发布后发现严重问题，先恢复 v0.6.0 可执行文件并保留数据库备份，再由修复版读取 prepared 案例。

## Open Questions

- 首版明确起点控件采用日期时间还是“从数据开头第 N 根”作为主输入，需要在实现前用现有数据集样例验证可理解性。
- prepared 案例是否允许从案例库直接编辑训练简报，还是只允许删除后重建；首个实现切片应以最小可恢复路径确定。
- 完成后默认打开交易复盘还是完成摘要，需要通过截图原型比较，不在领域模型中固化。
